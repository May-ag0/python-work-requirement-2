## Reflection

Good development practices help teams understand both the code and the decisions behind it. Documentation and diagrams make it easier to understand how a system is structured, while automated tests help ensure that changes do not break existing functionality. Version control makes it possible to track changes and see who changed what and why, which is important to keep track of the progress in a project. Pair or mob programming can contribute to knowledge sharing across the team instead of leaving important knowledge with one developer. Peer reviews also help improve code quality by and give developers insight into each other's work. Giving and receiving feedback can also be crucial for learning, because it exposes developers to different approaches and helps them reflect on and improve their own solutions. Together, these practices support shared understanding and make shared code ownership easier.
